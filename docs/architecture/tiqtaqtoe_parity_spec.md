# TiqTaqToe Official Engine vs. Python Stack Parity Specification

## 1. Executive Summary & Architectural Audit

This specification documents the complete reverse-engineering of the official JavaScript tournament engine (`local-tiqtaqtoe-server.js` + `@quantumplayed/quantum-game-engine`) for **TiqTaqToe (`quantumness = 0..4`, tournament target `quantumness = 3`)** and compares it line-by-line against the existing Python stack (`src/env/tictactoe.py` and `server.py`).

### Summary of Critical Findings
The official TiqTaqToe game engine does **not** use the classic Allan Goff cyclical-graph collapse rules implemented in `src/env/tictactoe.py`. Instead, it models the $3\times 3$ board as a **9-qutrit joint quantum system** ($\mathcal{H} = (\mathbb{C}^3)^{\otimes 9}$, total basis dimension $3^9 = 19,683$, sparse active states $\le 512$) powered by `@quantumplayed/quantum-game-engine` (`Operations.Shift`, `Operations.SqrtSwap`, `JointQuantumSystem.measureTarget`).

## 3. Exact Mathematical & Logical Specification of `OfficialTiqTaqToeEnv`

### 3.1 Quantum Statevector Representation
- **Basis**: 9 qutrits ($d=3$), alphabet $\Sigma = \{\text{'0'}: 0, \text{'X'}: 1, \text{'O'}: 2\}$.
- **State Dictionary / Vector**:
  - Sparse mapping `quantum_state: dict[str, complex]` (or equivalent indexed NumPy arrays of active basis indices `idx` $\in [0, 3^9-1]$ and `complex128` amplitudes).
  - Also supports parsing string-formatted statevectors (e.g. `"+0.71|010000000⟩ + 0.71|100000000⟩"`) in addition to the official JSON dict format `{"00XOOOO0O": {"real": 0.7071, "imaginary": 0.0}}`.
- **Gate Operations** (`Operations.js` + `local-tiqtaqtoe-server.js`):
  1. `Shift(amount)` on square `sq` (`amount = 1` for `'X'`, `amount = 2` for `'O'`):
     $$|s_0 \dots s_{\text{sq}} \dots s_8\rangle \mapsto |s_0 \dots ((s_{\text{sq}} + \text{amount}) \bmod 3) \dots s_8\rangle$$
  2. `SqrtSwap()` on `[sqA, sqB]`:
     For each basis state with amplitude $\alpha$:
     - If $s_{\text{sqA}} == s_{\text{sqB}}$: amplitude $\alpha$ is unchanged.
     - If $s_{\text{sqA}} \ne s_{\text{sqB}}$:
       - Original state $| \dots s_{\text{sqA}} \dots s_{\text{sqB}} \dots \rangle$ gets $\alpha \cdot (0.5 + 0.5i)$.
       - Swapped state $| \dots s_{\text{sqB}} \dots s_{\text{sqA}} \dots \rangle$ gets $\alpha \cdot (0.5 - 0.5i)$.
  3. **Sparsity & Serialization Filter**:
     - After each gate or single-entity measurement (`cleanAmplitudes`), drop entries with $|\text{re}| < 10^{-10}$ and $|\text{im}| < 10^{-10}$.
     - At the end of `serializeEngineState`, keep only states with $|\alpha|^2 \ge 0.0001$.
  4. **Projective Measurement** (`measureTarget` on square `sq`):
     - Compute marginal probabilities $P(s_{\text{sq}} = v) = \sum_{s: s[\text{sq}]=v} |\alpha_s|^2$ for $v \in \{\text{'0'}, \text{'X'}, \text{'O'}\}$.
     - Given outcome $v$ with $P(v) > 10^{-12}$, keep only basis states with $s[\text{sq}] = v$, scale their amplitudes by $1 / \sqrt{P(v)}$, and apply `cleanAmplitudes` ($10^{-10}$).

### 3.2 Move Execution & Branch Enumeration (`get_move_outcomes`)
- **Deterministic Moves**:
  - When a move `[sq]` or `[sq1, sq2]` does **not** trigger full-board projection (`!(isBoardFull && project && hasUnmeasuredSquares)`) and does not trigger decoherence:
    - Returns `[(1.0, next_env)]`.
- **Stochastic Moves (Measurement / Full-Board Collapse / Decoherence)**:
  - Whenever `measureSquares(roundState, squaresToMeasure)` is invoked (either by `[sq, "M"]`, full-board collapse, or decoherence):
    - In `local-tiqtaqtoe-server.js:500-505`, `system.measureTarget(system.entities[idx])` is called sequentially for `idx` in `squaresToMeasure`, followed by `serializeEngineState(system)` (`|\alpha|^2 \ge 0.0001`).
    - In `get_move_outcomes(move)`, instead of sampling `Math.random()`, we branch over all possible joint outcomes $(v_1, \dots, v_k) \in \{\text{'0'}, \text{'X'}, \text{'O'}\}^k$ of the measured squares that have non-zero Born probability $p_b > 10^{-9}$, applying the exact sequential `measureTarget` + `serializeEngineState` pipeline for each branch, and returning `[(prob_b, branch_env_b), ...]` whose probabilities sum to $1.0$.

### 3.3 Action Space & Deduplication
- Maintains full backward compatibility with the 46-action index space (`0..35` quantum pairs, `36..44` classical moves, `45..53` per-square measurement moves or deduplicated action `45` for legacy 46-output networks) AND provides native tournament move methods:
  - `get_available_moves(deduplicate_measurements: bool = False)`:
    - Returns exact tournament moves `[[sq], ..., [sq1, sq2], ..., [sq, 'M'], ...]`.
    - When `deduplicate_measurements=True`, deduplicates `[sq, 'M']` moves that belong to the same connected entanglement component (`squareToPair[sq]`), since in `doMove` (`local-tiqtaqtoe-server.js:579-588`) measuring any square in a pair measures the entire pair `[squareIndex, ...otherUnmeasuredInPair]` (which commutes in projective measurement!).

### 3.4 Dihedral $D_4$ Symmetry (`apply_d4_symmetry`)
- Implements all 8 symmetries `sym_idx in 0..7` of the $3\times 3$ board (4 rotations $\times$ 2 reflections) for:
  - Square indices $0..8$,
  - Tournament moves (`[sq]`, `[sq1, sq2]`, `[sq, 'M']`),
  - Action indices (`0..45`),
  - 111-dim state vectors, and
  - Cloned `OfficialTiqTaqToeEnv` instances (permuting the 9-qutrit basis strings and board metadata).
